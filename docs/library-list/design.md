# ライブラリ一覧 設計メモ (2026-11)

- 位置づけ: デスクトップの中央ペイン (曲の一覧 / カード表示 / アルバム / アーティスト) の
  **スクロールとデータ取得** の仕様。`docs/ui-spec.md` とユーザーガイドはこのメモと矛盾してはならない。
- 経緯: v0.21.0 までは 500 件ずつ取得し、末尾に近づくと追加取得していた。スクロールできる範囲が
  「読み込み済みの行」だけなので、スクロールバーを下まで引くと追加取得 → 内容が伸びる →
  つまみが上へ戻る、を繰り返し、数万曲のライブラリでは一番下へ行けなかった。
  **この仕様 (末尾での追加取得) は廃止した (仕様変更)。**

## 1. モデル

- **スクロール範囲は最初から全件ぶん。** 一覧を開いたらまず件数を取り、行数 (グリッドは
  `ceil(件数 / 列数)` 行) をその件数で確保する。スクロールバーのつまみの大きさは読み込みで変わらず、
  一番下まで引くと本当の最後の項目に着く。
- **データは見えている範囲だけ取る (ウィンドウ取得)。** 一覧を固定長のページ (200 件) に区切り、
  表示範囲と重なるページ + 前後 1 ページを取得する。
- **未取得の行はプレースホルダ。** 高さは実データの行・カードと同じで、取得後に位置がずれない。
- **全件はメモリに載せない** (`docs/ui-spec.md` 1.4)。ページキャッシュは LRU で 20 ページまで
  (表示中のページは捨てない)。全件ぶん持つのは件数と、必要になったときの track_id の列だけ。

対象は TrackTable (ライブラリ / プレイリスト / スマートプレイリスト / 検索・絞り込み)、
TracksView (カード表示)、AlbumsView、ArtistsView。Inbox と「最近再生した曲」は件数に上限のある
メモリ上の一覧で、同じ仕組みに配列を流す (件数 = 配列の長さ)。

## 2. 取得の規則

- 一覧の同一性は **キー** (スコープ・検索語・絞り込みタグ・並び順) で決まる。キーが変わったら
  キャッシュを捨てて先頭へ戻し、先頭のページをすぐ取る。
- **取り直し (リビジョン)**: ライブラリが変わったとき (編集・取り込み・削除など) はキーを変えずに
  件数と表示中のページを取り直す。スクロール位置は保ち、取り直しが届くまで古い行を表示し続ける
  (プレースホルダに戻さない)。表示範囲外のキャッシュは捨てる。
- **古い応答は捨てる。** キー・リビジョンが変わるたびに世代番号を進め、世代の違う応答は使わない。
- **同じページを二重に取らない。** 取得中のページは世代ごとに覚えておく。
- **スクロールバーを速く引いたとき、通過したページを取らない。** 足りないページが
  「キャッシュ済み・取得中のページの隣」で、取得中が 2 件未満なら (= 普通のスクロール) すぐ取る。
  それ以外 (= 離れた位置へのジャンプ) は 100 ms スクロールが止まってから、そのとき見えている範囲を取る。
- 件数が減って範囲外になったページは捨てる。

## 3. API (Tauri コマンド)

件数・ID 列は、ページ取得と **同じ WHERE 句の組み立て** を通す (件数とページが食い違わないこと)。

| 一覧 | ページ | 件数 | ID 列 (表示順) |
|---|---|---|---|
| ライブラリ / 検索 | `get_tracks` / `search_tracks` | `count_tracks(query?)` | `get_track_ids(query?, sortField, sortOrder)` |
| プレイリスト (スマート含む) | `get_playlist_tracks` / `get_smart_playlist_tracks` | `count_playlist_tracks(playlistId, query?)` | `get_playlist_track_ids(playlistId, query?, sortField, sortOrder)` |
| アルバム | `get_albums(…, query?, playlistId?)` | `count_albums(query?, playlistId?)` | — |
| アルバムの曲 | `get_album_tracks(albumKey, query?, playlistId?)` | — | — |
| アーティスト | `get_artists(…, query?)` | `count_artists(query?)` | — |

- Rust 側の単一の組み立て: ライブラリ / 検索は `Database::search_where`、通常プレイリストは
  `static_playlist_filter`、スマートプレイリストは `smart_playlist_matched` (評価 → 並べ替え → 検索の積)、
  アルバムは `album_scope_where`、アーティストは `artist_where`。ページ・件数・ID 列はそれぞれ同じ関数を使う。
- **アルバム表示はどのスコープでもサーバ集約。** プレイリスト / 検索のときは、その範囲の曲だけで
  アルバムを束ね (曲数・カバー・合計時間もその範囲の曲で数える)、展開したときの曲もその範囲の曲だけ。
  プレイリストに同じ曲が複数回入っていても 1 曲として数える。
- 契約はテストで固定する: 「件数 == 全ページを連結した長さ」「ID 列 == 全ページを連結した track_id の列」
  (`src-tauri/src/db/` の `windowed_list_*` テスト。ジャンルの完全一致・プレイリスト・スマートプレイリストを含む)。

## 4. フロントエンドの構成

- `src/lib/windowedList.ts` — 純関数 (ページ計算・LRU キャッシュ・取得タイミングの判定)。
  `tests/desktop/windowedList.test.ts` で固定。
- `src/hooks/useWindowedList.ts` — `useWindowedList({ key, revision, count, pageSize, fetchPage })`。
  世代管理・重複排除・キャッシュ・スクロール停止待ちを持つ唯一の hook。3 つのビューが共用する。
- `src/lib/trackListQuery.ts` — ストアの状態から「どの一覧か」(`TrackListQuery`) とキーを決める純関数。
  `src/api/trackList.ts` がそれを各コマンドへ振り分ける。
- `src/hooks/useTrackList.ts` — 曲の一覧 (TrackTable / TracksView) 用の薄い配線。件数の取得、
  ID 列の遅延取得 (`getIds`)、選択中の曲の解決 (`resolveTracks`)。
- `src/lib/gridRows.ts` `gridLayout` — 件数と列数からグリッドの行を決める。展開行は
  「読み込み済みで、展開中の項目」の行の直後に 1 行だけ差し込む。行キーは展開の開閉で変わらない。
- ビュー (TrackTable / TracksView / AlbumsView / ArtistsView) は描画と操作だけを持つ。
- ストアの `tracks` は **メモリ上の一覧 (Inbox / 最近再生した曲) 専用**。ライブラリ・プレイリスト・
  検索では空。表示中の件数は `listCount`、ライブラリ変更の通知は `libraryRevision`。

## 5. 操作 (読み込んでいない行をまたいでも同じ結果になること)

選択は **track_id の集合** で持ち、範囲選択の起点とカーソルは **行番号 + track_id** で持つ。
行番号から track_id が要るとき、読み込み済みならキャッシュから、無ければ ID 列を取る。

| 操作 | 方法 |
|---|---|
| クリック / Ctrl・Cmd クリック | 行の track_id を選択に出し入れ |
| Shift クリック / Shift+矢印 | 起点〜対象の行番号の範囲を ID 列から切り出す |
| Ctrl・Cmd+A | ID 列の全件 |
| ↑ ↓ / PageUp PageDown / Home End | 行番号を動かし、その行へスクロール (Shift で範囲を伸ばす) |
| ダブルクリック / Enter / メニューの再生 | ID 列の全件をキューに入れ、その行から再生 |
| 行のドラッグ | 選択中の track_id を表示順で渡す |
| 右クリックの操作 | 選択中の track_id に適用。曲の情報が要る操作 (Get Info・削除・Crate) は ID から取り直す |
| プレイリスト内の並べ替え (ドラッグ / Alt+↑↓) | 書き込みの直前に全曲順を取り直して移動し、取り直す |
| 並び順・検索・スコープの変更 | キーが変わる → 先頭へ戻る |
| ライブラリの変更 | リビジョン → スクロール位置を保って取り直す。件数も取り直す |

選択は、一覧を取り直すたびに解除する (v0.21.0 までと同じ。並べ替えの直後だけ選択を戻す)。

## 6. グリッドの展開行

- 展開できるのは読み込み済みのカードだけ (プレースホルダはクリックできない)。
- 展開中の項目は「項目キー + 開いたときの通し番号」で覚える。取り直しで位置がずれたら、
  読み込み済みの項目から同じキーを探し直す。見つからなければ閉じる。
- 行キー: グリッド行 `g:<列数>:<行番号>`、展開行 `x:<項目キー>`。展開の開閉で実測キャッシュを捨てない
  (`docs/refactor/design.md` の規則のまま)。
