# macOS AirPlay 出力の検証記録 (P0-A)

Crateforge は AirPlay を自前では実装しない。macOS で AirPlay スピーカーを OS のサウンド出力に選ぶと
CoreAudio の出力デバイスとして扱われるため、その経路で鳴らせるかを検証する。
設計上の位置づけは `docs/cast/design.md` の「7. macOS AirPlay (P0-A)」を参照。

**現在のステータス: 未実施（実機なし）。** 以下のコード解析は読解に基づく見込みであり、実機での動作確認は済んでいない。

## 1. コードレベルの解析

- 出力は `rodio` / `cpal` 経由で OS のオーディオデバイスへ送る。macOS では cpal が CoreAudio のデバイスを列挙する。
- macOS で AirPlay スピーカーを「システム設定 → サウンド → 出力」で選ぶと、CoreAudio 上の出力デバイスとして現れる想定
  (OS が AirPlay へのエンコード・送信を担当し、アプリからは通常の出力デバイスに見える)。
- `src-tauri/src/commands/output_device.rs` は、設定 → 一般 → 出力デバイスが **「システム既定」** のとき、
  既定出力を `DEFAULT_POLL` (3 秒) ごとに確認し、OS 側で既定が変わると出力を開き直して追従する
  (再生中の曲・位置・再生/一時停止・キュー・音量は維持)。
- したがって「OS の出力を AirPlay にする → 数秒以内に Crateforge が追従」という経路が成立する見込み。
  明示的にデバイス一覧から AirPlay デバイスを選ぶ経路も、一覧に列挙されれば同様に使える。
- `AVRoutePickerView` は導入しない (P0 の範囲外)。
- 未確認の点: AirPlay デバイスが cpal の一覧に出るか / 追従時の音切れ長 / AirPlay 固有の遅延 (数秒) による
  シーク・一時停止の体感 / サンプルレート・チャンネル構成の差。

## 2. 手動テスト手順

前提: macOS 機 (Apple Silicon / Intel の別を記録)、AirPlay 2 対応スピーカー (HomePod 等) または AirPlay 受信可能な Mac / Apple TV。
同一ネットワーク。Crateforge は最新ビルドを使用し、MP3 / AAC / FLAC を含む数曲をライブラリに用意する。

| # | 手順 | 期待結果 |
|---|---|---|
| 1 | Crateforge を起動し、設定 → 一般 → 出力デバイス を **システム既定** にする | 内蔵スピーカー等で通常再生できる |
| 2 | 曲を再生したまま、システム設定 → サウンド → 出力 (またはコントロールセンター) で AirPlay スピーカーを選ぶ | 数秒以内に AirPlay スピーカーから鳴り始める。曲・位置・再生状態は維持され、トーストの異常通知は出ない |
| 3 | 一時停止 → 再生、シーク、音量変更を行う | AirPlay 側で反映される (遅延は許容、操作不能にならない) |
| 4 | 曲の自動送り (キュー、シャッフル、リピート) を数曲分確認する | 曲間で止まらず、AirPlay 出力のまま続く |
| 5 | 設定 → 一般 → 出力デバイス の一覧を「更新」で取り直す | AirPlay デバイスが一覧に出るか記録する (出る / 出ない) |
| 6 | 一覧に出る場合、そのデバイスを明示的に選ぶ | AirPlay スピーカーから鳴る。選択は名前で保存される |
| 7 | 再生中に AirPlay を OS 側で内蔵スピーカーへ戻す (システム既定のまま) | 数秒以内に内蔵スピーカーへ追従する |
| 8 | 再生中に AirPlay スピーカーの電源を切る / ネットワークから外す | クラッシュしない。出力が既定へ戻る、または無音になる挙動を記録する |
| 9 | AirPlay 出力のまま Crateforge を再起動する | 起動後の出力先と、トースト通知の有無を記録する |
| 10 | 5 分以上連続再生する | 音切れ・ノイズ・ドリフトが無いか記録する |

記録する項目: macOS バージョン、機種、AirPlay デバイスの種類、ネットワーク構成 (Wi-Fi / 有線、同一 AP か)、体感遅延、問題点。
