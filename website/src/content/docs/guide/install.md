Crateforge は Windows（x64 / ARM64）/ macOS / Linux に対応しています。最新版は GitHub の
[Releases](https://github.com/tainakanchu/crateforge/releases/latest) から入手できます。

> 画像は後日追加

## ダウンロードと配布形態

| OS | 配布形態 | 備考 |
|---|---|---|
| **Windows（x64）** | 単体 `.exe` / ポータブル `.zip` / `.msi` / セットアップ `.exe` | アプリ内の自動更新に対応 |
| **Windows（ARM64）** | ポータブル `.zip` / セットアップ `.exe`（`.msi` なし） | アプリ内の自動更新に対応 |
| **macOS** | `.dmg`（Apple Silicon ネイティブ） | **未署名**。初回は Gatekeeper の回避が必要 |
| **Linux** | `.AppImage`（単一ファイル） / `.deb` | |

### Windows

**PC の種類に合ったファイルを選んでください。** ファイル名にアーキテクチャが入っています。

| PC | ポータブル版 | インストーラ版 |
|---|---|---|
| 一般的な Windows PC（Intel / AMD、x64） | `Crateforge_<版>_x64_portable.zip` | `Crateforge_<版>_x64-setup.exe` / `Crateforge_<版>_x64_en-US.msi` |
| ARM 版 Windows（Snapdragon の Copilot+ PC など、ARM64） | `Crateforge_<版>_arm64_portable.zip` | `Crateforge_<版>_arm64-setup.exe` |

- どちらか分からないときは **設定 → システム → バージョン情報** の「システムの種類」を見てください（「ARM ベース プロセッサ」なら ARM64）。
- **`.msi` は x64 専用** です。ARM64 版はセットアップ `.exe` かポータブル `.zip` を使ってください。
  名前に `arm64` の付かない単体の `crateforge.exe` も x64 版です。
- ARM64 の PC でも x64 版はエミュレーションで動きますが、ARM64 版のほうが高速です。
- アプリ内アップデートは **今使っている版と同じアーキテクチャ** のファイルを自動で選びます（x64 版が ARM64 版に、またはその逆に入れ替わることはありません）。
- ARM64 版では、変換用の ffmpeg も ARM64 版を自動取得します。USB 書き出しに使う rbx-cli は ARM64 版がまだ無いため、当面は x64 版をエミュレーションで使います（[USB 書き出し](../usb-export/)）。

- **インストーラ版（セットアップ `.exe` / `.msi`）** — 通常のインストール。
  インストーラからの **デスクトップショートカット作成は既定でオフ** です（必要ならインストール時に有効化してください）。
- **ポータブル版（`.zip`）** — 解凍して `crateforge.exe` を起動するだけ。インストール不要です。

いずれの版でも、アプリ内アップデートは通常 **exe をその場で差し替えて再起動するだけ** なので高速で、
SmartScreen の警告も出ません（v0.6.3 以降）。

:::caution
**v0.12.0 への更新はインストーラ経由になります。** この版では exe の外側（アプリの権限設定 / capabilities）が
変わったため、その場差し替えでは足りません。アプリ内アップデートはインストーラを自動でダウンロードして起動するので、
表示に従って進めてください（ポータブル版はこれまでどおり zip の差し替えで更新できます）。
:::

### macOS

未署名のため、初回起動時に Gatekeeper の警告が出ます。次のいずれかで回避してください。

- Finder で `.app` を **右クリック → 「開く」**
- もしくはターミナルで `xattr -cr /Applications/Crateforge.app`

### Linux

- `.AppImage` は実行権限を付けて起動します（`chmod +x ./Crateforge*.AppImage && ./Crateforge*.AppImage`）。
- `.deb` はパッケージマネージャでインストールします。

## 初回起動

1. アプリを起動すると空のライブラリが開きます。
2. 既存の `iTunes Library.xml` を持っている場合はツールバーの **「取り込み ▾」→「iTunes XML を取り込む…」** で取り込みます（[ライブラリ取り込み](../import/)）。
3. XML を持っていない場合は **「ファイルを追加」** で手元の音楽ファイルを直接取り込めます。

ライブラリの真実は SQLite (WAL) に常駐するため、初回取り込み後は次回以降すぐに開けます。

## アプリ内の自動アップデート

新しい GitHub Release が公開されると、ウィンドウ上部に **非ブロッキングなバナー** で通知されます。
リリースノート（日本語・英語の併記）は折りたたみ表示で確認できます。

更新の適用には次の選択肢があります。

- **今すぐ更新** — ダウンロードしてその場で適用・再起動します。
- **閉じるときに更新** — いまは使い続け、**ウィンドウを閉じるタイミングで自動的に適用** します（起動時に作業を中断されません）。

:::caution
アプリ内の自動更新は **Windows 専用** です。macOS / Linux は [Releases](https://github.com/tainakanchu/crateforge/releases/latest) から
手動でダウンロードして入れ替えてください。
:::

## ライブラリのバックアップ

解析結果・スキップ回数・スマートプレイリストの条件・同期状態などは iTunes 互換 XML には含まれません。
これらを含むライブラリ本体（`library.db`）は、**設定 →「ライブラリ」** のバックアップ項目から扱えます。

- **今すぐバックアップ** — `library.db` 全体を保存します（保存先を指定できます）。
- **バックアップから復元…** — 選んだバックアップでライブラリを置き換えます。
  復元前に自動で整合性チェックを行い、壊れているファイルでは上書きしません。
- **整合性チェック** — `library.db` が壊れていないか検査します（`PRAGMA integrity_check`）。
- **最適化 (VACUUM)** — 削除された分のディスク領域を回収し、ファイルを再編成します。
  曲数が多い場合は数秒〜数十秒かかることがあります。
- **技術情報を再読み取り** — ビットレート・サンプルレート・ファイルサイズ・コーデックが未取得の曲だけを
  ファイルから読み直します（以前のバージョンで取り込んだ曲向け）。曲名などの編集内容は変更しません。
- **自動エクスポート時にあわせてバックアップ**（既定 ON）— iTunes 互換 XML の
  [自動エクスポート](../import/)が成功したときに `library.db` もバックアップします。
  自動バックアップは **直近 5 件** を保持し、前回から 30 分未満のときはスキップします。

:::caution
復元はライブラリを置き換える操作で、元に戻せません（確認ダイアログが出ます）。
また、トークンなど一部の状態は起動時にのみ読み込まれるため、**復元後はアプリの再起動が必要** です。
:::

## ショートカット（デスクトップ）

Windows のインストーラはデスクトップショートカットを **既定で作成しません**。
必要な場合はインストール時のオプションで有効化してください。
