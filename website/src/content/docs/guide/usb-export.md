プレイリストやフォルダを、**CDJ / XDJ で読める rekordbox 互換の USB** に書き出せます（音声ファイル・解析〔ビートグリッド / 波形 / キー〕・キューポイント・プレイリスト・アートワーク）。
書き出しは **同期** として動き、2 回目以降は変わった曲だけを書き換えます。

> 画像は後日追加

:::caution
rekordbox・CDJ・XDJ は AlphaTheta 株式会社の商標です。Crateforge と rbx-cli は同社とは **無関係** で、同社の承認も受けていません。
また、この機能は **開発者の手元の実機（CDJ / XDJ）ではまだ検証していません**。本番の現場で使う前に、手持ちのプレーヤーで読み込み・キュー位置・グリッドを必ず確認してください。
:::

## 書き出す

1. サイドバーでプレイリストかフォルダを **右クリック →「USB に書き出し…」**（またはツールバーの **「USB に書き出し」**。狭い幅では ⋯ メニューの中）。
2. **書き出すプレイリスト** を選びます。フォルダを選ぶと配下のプレイリストを **階層ごと** 書き出します。スマートプレイリストは書き出し時点の内容で書き出します。
3. **書き出し先** を選びます。接続中のボリュームの一覧から USB を選ぶか、「フォルダ…」で任意のフォルダを指定します。前回の書き出し先は記憶されます。
4. **オプション** を決めます（下記）。
5. **「計画を確認」** を押すと、USB には何も書かずに計画を作ります。コピーする曲 / 再利用する曲、解析の出どころ（新規 / キャッシュ / USB 上の解析を再利用）、転送量と空き容量、Traktor との対応付け、見つからないファイル、注意点が表示されます。
6. **「書き出す」** で開始します。工程（準備 → 解析・タグ読み取り → 変更チェック → USB へコピー → データベース作成 → 検証 → 反映）ごとに進捗が出ます。
7. 完了したら **「取り出し」** で USB を安全に取り外せます（一覧にあるボリュームのみ。強制はしません）。

書き出し中もダイアログは閉じられます。進捗は画面右下（プレーヤーバーの上）のカードに出て、クリックするとダイアログに戻ります。
**「中止」** を押すと、曲の区切りで止まります。中止・失敗・取り外しのどの場合も、**USB には以前の内容がそのまま残ります**（新しい内容は退避領域に書いてから一度に切り替えるため）。

### オプション

| 項目 | 内容 |
|---|---|
| **Traktor のキュー/グリッドを使う** | 下の「Traktor のキュー/グリッド」を参照。既定はオフ |
| **アートワークを書き出す** | 音声ファイルに埋め込まれた画像をプレーヤー用に縮小して書き出します |
| **USB から消す** | 今回の内容に含まれない、以前書き出した曲を USB から削除します（プレイリストは常に今回の内容に揃います） |
| **デバイス名** | プレーヤーに表示される名前。空欄なら変更しません |
| **詳細設定** | Traktor の `collection.nml` の場所、MP3 オフセット (ms) |

### 書き出す内容

- 曲名・アーティスト・アルバム・ジャンル・コメント・年・トラック番号・ディスク番号・再生回数・追加日・レーティング（0〜5 の星。半星は切り上げ）は **Crateforge のライブラリの値** を使います。
- **キー** は Crateforge の実効キー（手動の上書き、無ければ解析値）を rekordbox の表記（`Am` / `F#m` など）で書きます。無い曲は書き出し時の解析結果を使います。
- **BPM・ビートグリッド・波形** は書き出し時に解析して作ります（Traktor のグリッドを使う場合はそのグリッド）。表示 BPM はグリッドと同じテンポになります。
- **ファイルが見つからない曲**（外付けドライブや NAS が未接続など）は、計画に件数と例が出ます。そうした曲もプレイリストからは外さずに rbx-cli に渡します:
  - 以前この USB に書き出していない曲は、スキップされます。
  - **以前この USB に書き出した曲** が含まれていると、USB 上の曲を消さないよう **USB を変更せずに書き出しを中止** します。ドライブを接続するか、曲の場所を直してから書き出してください（「USB から消す」がオンでも、見つからないだけの曲が USB から消えることはありません）。

## Traktor のキュー/グリッド

Crateforge 自体はキューやビートグリッドを持ちません。**「Traktor のキュー/グリッドを使う」** をオンにすると、書き出しのたびに Traktor の **`collection.nml`** を読み、曲を **ファイルパス** で突き合わせて、Traktor のキューとグリッドを USB に書きます（Crateforge のライブラリには保存しません）。

- `collection.nml` は `ドキュメント/Native Instruments/Traktor <バージョン>/` の **最新版を自動検出** します。違う場所なら詳細設定（または **設定 → USB 書き出し**）で指定します。
- パスが一致しない曲は、**ファイル名とファイルサイズ** が一意に一致する場合だけ対応付けます。計画に一致 / 不一致の件数と例が出ます。
- macOS では、クローンやバックアップ用のボリュームに **同じパスの曲** があると、どれが本物か決められないことがあります。その場合は起動ボリューム上の曲を使い、起動ボリュームに無ければ **その曲には Traktor のキュー/グリッドを使いません**（計画に「候補が複数」として出ます）。
- 変換規則:
  - グリッドマーカー → ビートグリッド（Traktor の BPM で一定テンポ。マーカーが複数あればそれぞれを起点にします）
  - キュー / フェードイン / フェードアウト / ロード → キューポイント、ループ → ループ
  - ホットキュー 1〜8 → ホットキュー A〜H、ホットキューに割り当てていないもの → メモリーキュー
  - キューの名前 → キューのコメント
- **Traktor に見つからない曲**、またはこのオプションが **オフ** のときは、キューもグリッドも送りません。USB 上にすでにあるキューはそのまま残り、グリッドは解析で作ります。
- Traktor に一致した曲は **Traktor の状態に揃えます**。Traktor でキューが無い曲は、USB 上のキューも消えます。

### MP3 のずれ（MP3 オフセット）

Traktor と rekordbox / CDJ では MP3 のデコード開始位置の扱いが異なり、**MP3 のキュー・グリッドが数十 ms ずれることがあります**。
詳細設定の **「MP3 オフセット (ms)」** で、Traktor から取り込む MP3 のキュー/グリッドをずらせます（正の値で後ろ、負の値で前）。既定は **0 ms** です。
ずれ方はファイルやエンコーダによって異なり得るため、**正しい値は実機で確認して調整してください**（Crateforge は推測値を入れていません）。

### CDJ で保存したキューとの競合

CDJ で USB にキューを保存すると、USB 上の解析ファイルが書き換わります。その後に Traktor のキューを送ると CDJ で保存したキューが失われるため、
書き出しは **USB を変更せずに中止** され、説明が表示されます。このとき:

- **「USB 上のキューを優先（Traktor のキューを送らない）」** で再試行すると、今回は Traktor のキューを送らずに USB 上のキューを残します（グリッドは Traktor のものを送ります）。
- CDJ で保存したキューを残したまま Traktor 側と揃えたい場合は、rekordbox などで USB から取り込んでから書き出してください。

「Traktor のキュー/グリッドを使う」がオフなら、CDJ で保存したキューは毎回そのまま残ります。

## 速度とキャッシュ

- **初回は時間がかかります**: 全曲の解析と USB への書き込みが必要です。
- 2 回目以降は、**解析キャッシュ**（PC 側。曲の内容と解析設定が同じなら再利用）と USB 上のファイルを再利用し、変わった曲だけをコピー・解析します。
- ただし変更を確実に検出するため、**毎回、元ファイルと USB 上のファイルをすべて読み込みます**。曲数が多い USB では、何も変わっていなくても読み込みの時間がかかります。
- **rekordbox が起動中は書き出せません**（同じ USB に書き込む可能性があるため）。

## rbx-cli について

USB への書き出しは、外部ツール **[rbx-cli](https://github.com/tainakanchu/rbx-cli)**（[rbxport](https://github.com/chrisle/rbxport) ベース）が行います。

- Crateforge は rbx-cli を **別プロセスとして起動し、JSON でやり取りするだけ** です。本体には組み込まず、配布物にも含めません。
- rbx-cli がまだ無いときは、書き出しダイアログ（または **設定 → USB 書き出し (rbx-cli)**）の **ダウンロード** で、上流の GitHub Release から取得します。チェックサム（SHA-256）を確認してから、アプリのデータフォルダに保存します。
- 使われる rbx-cli は「設定で指定したパス → ダウンロード済みのもの → PATH 上の `rbx-cli`」の順に探し、対応するプロトコルのものだけを使います。自分でビルドした rbx-cli も、設定の **「パスを指定…」** で使えます。
- 配布バイナリは Windows（x86-64）/ macOS（Apple Silicon / Intel）/ Linux（x86-64、glibc 2.39 以降）向けです。

:::note
rbx-cli は GPL-2.0-or-later（配布バイナリは LGPL-3.0 の部品を含むため実質 GPL-3.0）のソフトウェアです。Crateforge（MIT）とはリンクせず、外部コマンドとして呼び出すだけです。
:::
