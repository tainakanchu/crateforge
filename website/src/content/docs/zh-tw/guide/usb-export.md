可將播放清單與資料夾匯出到 **CDJ / XDJ 可讀取、與 rekordbox 相容的 USB**（音訊檔、分析資料〔節拍格線 / 波形 / 調性〕、Cue 點、播放清單、封面）。
匯出以 **同步** 的方式運作，第二次起只會重寫有變更的曲目。

> 圖片日後補上

:::caution
rekordbox、CDJ、XDJ 是 AlphaTheta 株式會社的商標。Crateforge 與 rbx-cli 與該公司 **無關**，亦未獲其認可。
此外，此功能 **開發者尚未在實機（CDJ / XDJ）上驗證**。正式上場前，請務必在自己的播放器上確認讀取、Cue 位置與格線。
:::

## 匯出

1. 在側邊欄 **右鍵點選播放清單或資料夾 →「USB に書き出し…」**（匯出到 USB），或使用工具列的 **「USB に書き出し」**（視窗較窄時在 ⋯ 選單內）。
2. 選擇 **要匯出的播放清單**。選擇資料夾時，會 **連同階層** 匯出其下的播放清單。智慧播放清單以匯出當下的內容匯出。
3. 選擇 **匯出位置**：從已掛載磁碟區的清單中選擇 USB，或以「フォルダ…」（資料夾…）指定任意資料夾。會記住上次的匯出位置。
4. 設定 **選項**（見下方）。
5. 按 **「計画を確認」**（確認計畫）會在不寫入 USB 的情況下建立計畫：要複製 / 重複使用的曲目、分析來源（新分析 / 快取 / 重複使用 USB 上的分析）、傳輸量與剩餘空間（無論匯出目的地是 USB 還是任意資料夾，都以所在磁碟的剩餘空間檢查）、與 Traktor 的對應、將保留 CDJ 上變更之 Cue / 格線的曲目、找不到的檔案與注意事項。
6. 按 **「書き出す」**（匯出）開始。會依階段（準備 → 分析・讀取標籤 → 變更檢查 → 複製到 USB → 建立資料庫 → 驗證 → 套用）顯示進度。
7. 完成後可用 **「取り出し」**（退出）安全地退出 USB（僅限清單中的磁碟區，不會強制退出）。

匯出期間也可以關閉對話框。進度會顯示在畫面右下（播放列上方）的卡片，點擊即可回到對話框。
按 **「中止」**（取消）會在曲目之間的空檔停止。無論是取消、失敗或拔除，**USB 都會保留先前的內容**（新內容會先寫到暫存區，再一次切換）。
若匯出途中 Crateforge 被強制結束或當機，rbx-cli 也會偵測到並中止匯出（不會在無人看管下繼續寫入 USB）。

### 選項

| 項目 | 說明 |
|---|---|
| **Traktor のキュー/グリッドを使う**（使用 Traktor 的 Cue / 格線） | 見下方「Traktor 的 Cue / 格線」。預設關閉 |
| **アートワークを書き出す**（匯出封面） | 將音訊檔內嵌的圖片縮小後匯出給播放器使用 |
| **USB から消す**（從 USB 刪除） | 刪除先前匯出、但這次不包含的曲目（播放清單一律與這次內容一致） |
| **CDJ で変更したキュー/グリッドを優先する**（優先使用在 CDJ 上變更的 Cue / 格線） | 上次匯出後在 CDJ 上變更過 Cue 或格線的曲目，只有這些曲目會保留 USB 上的 Cue / 格線（請參閱下方「與 CDJ 上變更的 Cue / 格線衝突」）。預設關閉（會中止匯出並告知） |
| **デバイス名**（裝置名稱） | 播放器顯示的名稱。留空則不變更 |
| **詳細設定**（進階） | Traktor `collection.nml` 的位置、MP3 偏移（ms） |

### 匯出的內容

- 曲名、演出者、專輯、類型、註解、年份、曲目編號、光碟編號、播放次數、加入日期與評分（0〜5 顆星，半星無條件進位）使用 **Crateforge 音樂庫的值**。
- **調性** 以 Crateforge 的實際調性（手動覆寫，否則為分析值）並以 rekordbox 的寫法（`Am`、`F#m` 等）寫入。沒有調性的曲目使用匯出時的分析結果。
- **BPM、節拍格線、波形** 於匯出時分析產生（使用 Traktor 格線時則為該格線）。顯示的 BPM 與格線的速度一致。
- **找不到檔案的曲目**（例如外接硬碟或 NAS 未連接）會在計畫中顯示件數與範例。這些曲目仍會交給 rbx-cli，也不會從播放清單中移除：
  - 先前未匯出到此 USB 的曲目會被略過；
  - 若此 USB **已有先前匯出的這類曲目**，為了不刪除 USB 上的複本，匯出會 **在不變更 USB 的情況下中止**。請連接硬碟（或修正曲目位置）後再匯出。即使開啟「USB から消す」（從 USB 刪除），只是找不到檔案的曲目也不會從 USB 刪除。

## Traktor 的 Cue / 格線

Crateforge 本身不保存 Cue 與節拍格線。開啟 **「Traktor のキュー/グリッドを使う」** 後，每次匯出時都會讀取 Traktor 的 **`collection.nml`**，以 **檔案路徑** 對應曲目，並將 Traktor 的 Cue 與格線寫入 USB（不會存入 Crateforge 音樂庫）。

- 會 **自動偵測** `文件/Native Instruments/Traktor <版本>/collection.nml` 的最新版本。若位置不同，請在進階設定（或 **設定 → USB 書き出し**）中指定。
- 路徑不一致的曲目，只有在 **檔名與檔案大小** 唯一相符時才會對應。計畫中會顯示相符 / 不相符的件數與範例。
- 在 macOS 上，若複製或備份用的磁碟區中有 **相同路徑的曲目**，可能無法判斷哪一首才是正確的。此時會使用開機磁碟區上的曲目；若開機磁碟區上沒有，**該曲目就不使用 Traktor 的 Cue / 格線**（計畫中會以「候補が複数」（多個候選）顯示）。
- 轉換規則：
  - 格線標記 → 節拍格線（以 Traktor 的 BPM 為固定速度；有多個標記時各自作為起點）
  - Cue / 淡入 / 淡出 / 載入 → Cue 點，Loop → Loop
  - Hot Cue 1〜8 → Hot Cue A〜H，未指派到 Hot Cue 的 → Memory Cue
  - Cue 名稱 → Cue 註解
- **Traktor 中找不到的曲目**，或此選項 **關閉** 時，不會送出 Cue 與格線：USB 上既有的 Cue 會保留，格線由分析產生。
- 與 Traktor 相符的曲目會 **與 Traktor 一致**：在 Traktor 中沒有 Cue 的曲目，USB 上的 Cue 也會被刪除。

### MP3 偏移

Traktor 與 rekordbox / CDJ 對 MP3 解碼起點的處理不同，**MP3 的 Cue 與格線可能相差數十毫秒**。
可在進階設定的 **「MP3 オフセット (ms)」**（MP3 偏移）中，調整從 Traktor 匯入的 MP3 Cue / 格線（正值往後，負值往前）。預設為 **0 ms**。
偏移量可能因檔案與編碼器而異，**請在實機上確認後調整**（Crateforge 不內建推測值）。

### 與 CDJ 上變更的 Cue / 格線衝突

在 CDJ 上將 Cue 存到 USB，或變更節拍格線時，USB 上的分析檔會被改寫。之後若送出 Traktor 的 Cue / 格線，CDJ 上的變更就會遺失，因此預設會 **在不變更 USB 的情況下中止** 匯出，並顯示說明與 **相關曲目**。此時：

- 按 **「CDJ の変更を優先して再試行」**（優先保留 CDJ 的變更並重試），會以相同內容（相同的播放清單、匯出目的地與選項；仍會送出 Traktor 的 Cue / 格線）重新匯出，但 **只有在 CDJ 上變更過的曲目會保留 USB 上的 Cue 與格線**，其他曲目寫入 Traktor 的 Cue / 格線。完成畫面會顯示「CDJ で変更されたキュー/グリッドを保持した曲: N」（保留了 CDJ 上變更之 Cue / 格線的曲目數）及這些曲目。
- 若每次都想這樣匯出，請開啟選項 **「CDJ で変更したキュー/グリッドを優先する」**（計畫畫面也會顯示將保留的曲目數）。
- 若不需要 CDJ 上的變更，可以匯出到另一個（空的）USB。

:::caution[CDJ 上的變更只會保留那一次]
即使優先保留 CDJ 的變更，也 **只會在那一次匯出中保留**。下一次匯出時，除非之後又在 CDJ 上變更，否則 **會再次寫入 Traktor 的 Cue / 格線**。若想一直保留 CDJ 上的變更，請在 Traktor 中做相同的修改（或用 rekordbox 等工具從 USB 匯入）。

此外，新型播放器 **只記錄在 OneLibrary（`exportLibrary.db`）中的 Cue 變更** 無法以此方式保留：即使優先保留 CDJ 的變更，匯出仍會中止。請用 rekordbox 從 USB 匯入，或匯出到另一個 USB。
:::

「Traktor のキュー/グリッドを使う」關閉時，CDJ 上儲存的 Cue 每次都會保留。

### 因其他原因中止時

為了不遺失 USB 上的內容，在下列情況下匯出也會 **在不變更 USB 的情況下中止**，並顯示原因（可得知時也會顯示相關曲目）：

- 上次匯出後，在 rekordbox 或 CDJ 上變更或刪除了 USB 上的曲目資訊、播放清單或 My Tag；
- USB 上有 rekordbox 等 Crateforge 以外的工具匯出的曲目或播放清單，或屬於其他資料庫；
- 「USB から消す」（從 USB 刪除）要刪除的曲目仍在 USB 的播放紀錄（History）中（請關閉「USB から消す」後再匯出）；
- 先前匯出過的曲目檔案找不到（請參閱上方「匯出的內容」）；
- 匯出途中有其他應用程式變更了 USB（請再匯出一次）。

## 速度與快取

- **第一次匯出較慢**：需要分析所有曲目並寫入 USB。
- 之後的匯出會重複使用 **分析快取**（電腦端；曲目內容與分析設定相同時重複使用）與 USB 上的檔案，只複製 / 分析有變更的曲目。
- 但為了確實偵測變更，rbx-cli **每次仍會讀取來源與 USB 上的所有音訊檔**。曲目多時，即使沒有變更也需要讀取時間。
- **rekordbox 執行中無法匯出**（它可能寫入同一個 USB）。

## 關於 rbx-cli

實際寫入 USB 的是外部工具 **[rbx-cli](https://github.com/tainakanchu/rbx-cli)**（以 [rbxport](https://github.com/chrisle/rbxport) 為基礎）。

- Crateforge 只會 **以獨立行程啟動 rbx-cli 並以 JSON 溝通**，不會內建於本體，也不隨附於發行檔。
- 尚未安裝 rbx-cli 時，可在匯出對話框（或 **設定 → USB 書き出し (rbx-cli)**）中 **下載**。會從上游的 GitHub Release 取得，確認 SHA-256 校驗碼後儲存到應用程式的資料資料夾。
- 需要 **rbx-cli 0.1.1 以上**（若先前下載的是 0.1.0，請依對話框的提示重新取得）。
- rbx-cli 依「設定中指定的路徑 → 已下載的版本」順序尋找，且只使用支援的協定版本與所需功能的版本（為了安全，不會自行使用 PATH 上的 `rbx-cli`）。若要使用自行建置的 rbx-cli，請透過設定中的 **「パスを指定…」**（指定路徑…）指定。
- 發行的執行檔支援 Windows（x86-64）/ macOS（Apple Silicon / Intel）/ Linux（x86-64，glibc 2.39 以上）。

:::note
rbx-cli 為 GPL-2.0-or-later 授權的軟體（發行的執行檔含有 LGPL-3.0 的元件，因此實質上為 GPL-3.0）。Crateforge（MIT）不會連結它，只會以外部指令呼叫。
:::
